## 下載與安裝

本次變更不恢復先前撤下的舊封包、不建立正式 Release，也不將同版本的新來源假稱為已驗收的舊封包。歷史檔案狀態見 [artifacts/README.md](artifacts/README.md)。可由下方開發流程建置目前來源，輸出在 `dist/`；後續候選需標明自己的版本、commit、SHA-256 及實測範圍。

本地測試請使用可棄置世界，同時啟用對應的行為包與資源包。宣告最低目標為 **Bedrock 26.60（manifest：1.26.60）**，依賴穩定版 `@minecraft/server 2.11.0`、`@minecraft/server-ui 2.0.0`。**必須啟用 Upcoming Creator Features**，供冰箱使用原生方塊容器；不要求 Beta APIs 或 POI 實驗功能。版本依據見 [容器能力核對](docs/NATIVE-CONTAINERS.md)。這不是所有版本／裝置均已實測的聲明。首次加入會收到指南；也可用工作台合成指南及基本設備。

**指南書**：Order To Cook 沿用自己的 `ordertocook:guide`，不是 Cookery 內的章節，也不要求安裝 Cookery 才能閱讀。指南參照 Cookery 的三級分類，提供六大章、十三個主題組與二十六篇教程，包含圖示、上一頁／下一頁、返回目錄及繁中／簡中／英文。既有物品與合成配方不變；基岩版仍以原生表單呈現，並非直接複製 Cookery 書本外觀。圖示來源與目前客戶端觀察範圍見 [獨立指南結構](docs/GUIDEBOOK.md)。

原作者補充確認不再是全面發布門檻；原署名、GPL、對應源碼、來源雜湊與實際品質檢查仍保留。證據及政策見 [素材登記](docs/ASSET_LICENSE_REGISTER.md)、[第三方聲明](THIRD_PARTY_NOTICES.md) 與 [發布檢查](docs/RELEASE_COMPLIANCE.md)。本作品不代表原作者或 Mojang/Microsoft 背書。

## 生存開店流程

1. **建立餐廳。** 合成並放置打單機、菜單立牌、操作台、包裝架、餐盤架、椅子及洗碗池。每家餐廳的打單機相隔超過 24 格。
2. **設定菜單。** 用食品點擊立牌加入菜式；不消耗食品。空手／蹲下點擊管理菜單。每種菜只算一份營養，不按手上堆疊數量計算。
3. **補充物資。** 用皮革補包裝架、乾淨餐盤補餐盤架。兩架要在操作台 **5 格內**；操作台、椅子及相關冰箱在餐廳附近 **24 格內**。
4. **開始營業並接單。** 點打單機開始營業，選一張候選單。接下打單機的一單後，同輪其他候選會消失；到店顧客的單獨訂單保留。
5. **準備成品食品。** 將訂單要求的食物放在背包或可使用的附近冰箱。手持有效訂單點操作台可直接裝盤／打包；空手點台可在同一頁查看菜名、數量與缺料。**操作台不是自動合成整道菜的機器**，它消耗的是已做好的食品。
6. **取成品交付。** 保持操作台上方空置；完成的盤子／包裹會擺在台上。點擊取走，拿在手上點擊相應顧客。蹲下擺放再取回會[保留整件成品資料](docs/PARITY.md#未交付的展示餐點)。外送包裹與訂單可顯示目的地及方向。
7. **收款、收盤與洗碗。** 完成訂單取得 oTc 幣及可能的小費。堂食餐點約 5 秒吃完，髒盤會保留在桌前；店主或員工點擊餐盤或下方桌面收取，再放進洗碗池，空手點擊開始並保持望著池子 4 秒。把乾淨盤補回餐盤架後可再次使用。同一桌前的舊盤須先收好才能交下一餐。
8. **擴建。** 用金幣升級餐廳、在打單機內買設備。工具箱可把兩格高的空木桶升為冰箱、空煙燻爐升為三槽爐灶、沒有盤子的洗碗池升為洗碗機。

普通單 **30 分鐘**、加急單 **10 分鐘**，從生成時計時。打單機預設累計 **10 分鐘營業運作時間**刷新，暫停／區域停止運作／關服時停計並保存餘時；餐廳最高 **8 級**。訂單期限按世界總tick計算：關服不倒數，伺服器運行時離開區域仍會到期。顧客反應、餐盤食品及廚電則只在原生區域模擬時累計tick，保存重開不補算關服時間。

> 預設立牌只有四道菜；40 種原版食品總營養為 159，只靠原版表最多升至 Lv.3。未發布來源加入 67 種正營養森羅食品及 72 種零營養飲品，完整目錄營養合計 490，可支持 Lv.7，仍不足原版 Lv.8 的 600。喜糖活動已結束，排除後為 470；其他取得限制見 [食品目錄](docs/FOOD-CATALOG.md)。飲品不增加營養，升級門檻維持原值。

| 設備 | 操作方式 |
| --- | --- |

## 明確的改編與未完成項

- 冰箱使用真實原生容器；爐灶與操作台採直接操作及單頁表單，沒有完全相同的 Java 專用槽位佈局與快捷鍵。
- 蹲下空手點擊冰箱上／下層可整理目前那層：同資料合併，依原先出現順序收攏；保留名稱與 metadata。原生堆疊上限不變，仍無食品限定與每格 128 件。

## 菜單與食品變體（未發布來源修正）

## 個人進度與設備資訊

使用指南選「個人進度」，或在可管理的打單機表單開啟同名入口。11 條清單可點開條件；詳情可以返回清單，關閉回遊戲。成功交單的結算金額（含小費與驚喜加賞）算在**實際交餐玩家**，跨店累計，花掉或撿起金幣不會改變該數字。

金牌餐廳按原作程式逐維度判定：同一玩家在同一維度擁有至少 4 間仍放置的餐廳，其中一間收益並列或獨占該維度第一。休息及區塊未載入的店仍算；已確認被拆的店不算。0 收益並列有效，跨維度 2＋2 間不等於 4 間。完整條件與來源見 [PROGRESSION.md](docs/PROGRESSION.md)。

看向 6 格內可使用的設備，HUD 顯示實際盤數、包材、洗碗 phase、冰箱分區占用槽位或爐灶進度。冰箱上層 27、下層 54 格。只看設備不建立庫存或搬動物品。第一行優先手洗進度；第二行保留主手有效外送票據／包裹的導航。手洗需雙手空，完成後重新持外送物品即可恢復導航。

## 管理員設定及相容

只有創造模式玩家、具有 `otc_admin` 標籤的玩家或伺服器端指令可更改全域設定。伺服器主控台沒有玩家時不能發放個人套組。

```mcfunction
/tag @s add otc_admin
/scriptevent ordertocook:kit
/scriptevent ordertocook:refresh
```

`kit` 是測試套組，`refresh` 是 24 格內打單機的測試刷新；**正常生存開店不需要它們**。

已接入目錄或供應介面的食品會自動識別。管理員若要覆寫其他已安裝食品的明確營養值，仍可使用原指令：

```mcfunction
/scriptevent ordertocook:food {"typeId":"example:your_dish","nutrition":12,"label":"你的料理"}
/scriptevent ordertocook:config {"currencyItem":"minecraft:emerald"}
/scriptevent ordertocook:config {"currencyItem":""}
```

`example:your_dish` 是說明用佔位 ID，必須替換成真的已安裝物品。空貨幣 ID 恢復 oTc 幣。自訂貨幣每件視為 1 單位；更改只影響之後的付款，不會把已持有的舊貨幣自動兌換。

測試刷新間隔及門檻也可調整，例如：

```mcfunction
/scriptevent ordertocook:config {"refreshSeconds":30,"upgradeNutrition":[0,25,40,60,80,100,120,140,159]}
```

上例**會偏離原版平衡**。原版門檻為 `[0,40,80,120,160,200,300,400,600]`，刷新 600 秒。烹調對應擴充入口見 `SMOKING_RECIPES`、`FUEL_TICKS` 及 [RUNTIME_ADAPTATIONS.md](docs/RUNTIME_ADAPTATIONS.md)。

## 開發與重現

需求：Node.js 22+、Python 3.12+。已生成的資源納入版本控制，正常建置不需要下載原作或安裝美術工具。

```sh
npm ci
npm run verify
python tools/check_compliance.py
```

CI 依 [tools/ci_scope.py](tools/ci_scope.py) 判斷改動範圍。只有已確認不參與建置的說明文件與 `docs/validation/` 文字觀察紀錄，才省略玩法測試、型別檢查與模型幾何重現；打包、署名、素材來源及發布規則檢查仍會執行。程式、資源、工具、工作流、版本或未知改動，以及 tag、手動執行或缺少比較基準時，均跑完整檢查；流程見 [build.yml](.github/workflows/build.yml)。

輸出位於 `dist/`，包含 `.mcaddon`、獨立 `.mcpack`、`SHA256SUMS.txt` 及 runtime 指紋。若修改來源模型或轉換器：

```sh
python -m pip install Pillow==12.3.0
python tools/convert_assets.py
npm run verify
```

轉換器預設使用 `upstream/reference/` 的固定來源子集，也可用 `--source /path/to/full/OrdertoCook` 指定完整上游 checkout。固定基準記錄於 [upstream/source.lock.json](upstream/source.lock.json)。

原生服務端測試需要從 [Minecraft 官方網站](https://www.minecraft.net/en-us/download/server/bedrock) 自行取得 Linux BDS，解壓到**沒有其他世界的獨立測試目錄**：

```sh
python tools/bedrock_smoke.py --server-dir /path/to/disposable-bds --mode initial
python tools/bedrock_smoke.py --server-dir /path/to/disposable-bds --mode reload
```

探針不隨正式安裝包啟用；它只會被測試工具注入一次性的測試副本。
