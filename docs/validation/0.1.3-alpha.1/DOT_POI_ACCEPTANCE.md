- npm 版本 **0.1.3-alpha.1**；BP/RP pack version 均 **[0,1,3]**，pack UUID 不變。最低 **Bedrock 26.60**，依賴 @minecraft/server **2.12.0-beta**、@minecraft/server-ui **2.0.0**；**Beta APIs + Points of Interest (POI)** 兩項實驗必開。不同世界版本與實驗條件不可當成同一輪。
- 候選來源 runtimeTreeSha256：**62500a0d5938f35c749ea77ae47ab4d2ccd1d5c046e10617a84d8bf021773184**（僅代表 runtime tree，不是 .mcaddon 的 SHA256）。最新 Actions 驗證應與實際檢出來源樹再核對，源碼有改動時不得照抄此值。
- **沒有獲確認的新版公開下載檔名／安裝包 SHA256。** 不得使用已撤下的 alpha.3 安裝包，不得把 GitHub Source ZIP 當 .mcaddon。dot 應從**同一精確 commit**本機打包，記錄輸出檔名、大小及自行實算 SHA256；若做不到，所有客戶端案例記「阻塞：未固定安裝包」，不要自行猜測。

## 2. 測試世界與執行順序

- **O-C（診斷）**：全新可棄置的 Bedrock 26.60+ 世界，只有此候選 BP/RP、Beta APIs 和 POI；可使用管理員套組或指令快速取樣，但在報告標明所做的改動。先測 D3-01～D3-09。
- **O-S（預設生存）**：另一個全新世界，使用原始設定；不帶入 O-C 的刷新縮時、給物、虛擬營養調參。完成實際開店→接單→備料→交付→收盤→洗碗閉環（D3-10）。
- **O-M（雙人）**：同一世界兩位真實玩家 A 店主、B 員工或非員工，至少一端觸控。記錄雙端客戶端版本、裝置、延遲、帳戶角色與變更時間。權限拒絕測試時雙方都設生存模式、移除 B 的 otc_admin（創造模式也授予管理員權限）。D3-11～D3-15。
- **O-U（舊世界副本）**：以原版 0.1.2-alpha.3 和相同 UUID BP/RP 在另一個世界建立真實餐廳、庫存、訂單、命名 ItemStack；**正常停服後完整備份，再克隆 O-U**，僅在副本升級至 0.1.3 並開兩項實驗。不得只回退包、不還原世界備份；D3-16～D3-18。
- **O-V（展示／對照）**：第一／第三人稱、近鏡、4 朝向、界面／聲音、特別是舊版已觀察失敗的冰箱幾何、洗盤粒子 Molang、進度灰字，以及獨立指南的像素書圖標和章節層次；D3-19～D3-21。Java 參考固定 [原作 e59e3db](https://github.com/breezeth-CN/OrdertoCook/tree/e59e3dbcabe19b783d9adb933db5fcb8bc1e4642)，實際 Java 發行版本及光照/FOV 均須記下。
- **O-P（效能／配套）**：基線先跑僅 OTC，再在可棄置的完整配套副本測已安裝的森羅 Food V1；D3-22～D3-23。不得把相容配套注入 O-C 的基線記錄，也不得聲稱有 FPS/TPS 改善百分比而未測量。

建議測試順序：**來源／包核對 → D3-01～D3-05 基本 POI → D3-06～D3-10 生存與恢復 → D3-11～D3-15 雙人 → D3-16～D3-18 升級 → D3-19～D3-23 視覺效能與配套**。有致命故障時，依賴它的項目記阻塞，其他獨立案例繼續，不需等使用者再次授權普通測試。

## 4. 證據與結論

- 每個案例 **一個提交 SHA＋一個設備／角色＋一個結果**；結果僅「未執行／通過／失敗／阻塞」。舊版客戶端 FAIL 記錄不覆蓋，應獨立重測。
- 報告首屏必填：dot 執行時間與時區、候選 HEAD、安裝包檔名／大小／**自行實算 SHA256**、BP/RP UUID/版本、完整 Bedrock 客戶端及 BDS 版、兩項實驗、裝置／OS／輸入方式、世界與角色代號。隱藏物品 proof／動態屬性不可由 UI 猜測，未知填未知。
- FAIL 附：預期／實際、精確步驟、座標與朝向、操作前後物品名稱／數量、雙端實際時序、Content Log 及 15 秒以上的畫面錄影。影片、截圖逐檔計算 SHA256 或有固定可開連結；敏感世界、IP、玩家資訊與完整存檔只放在私有證據空間，**不可貼入公開 PR**。
- 隨機情境需填嘗試次數及每個被觀察的分支；沒抽到不是通過。可見問題即使 log 沒有 error 仍 FAIL，註明「該時段未見 Content Log error」。
- 每輪複製 [結果模板](DOT_POI_REPORT_TEMPLATE.md) 至獨立新檔，建議命名 client-YYYYMMDD-device-dot.md；最後列出 **PASS／FAIL／BLOCKED／NOT RUN 數量**、仍需修復的具體 ID、待提交 PR 與重測的下一個 SHA。不要直接把本清單狀態改成通過。
- **合併／發布門檻**：基本開店、真實支付與庫存不複製不遺失、存檔升級、雙人權限／座位、指定客戶端互動與高優先故障必須有相同固定候選的證據。CI/BDS 綠燈本身不批准 Release/LIVE；保留 Draft、client=false、production_ready=false，直到真實驗收完成。
