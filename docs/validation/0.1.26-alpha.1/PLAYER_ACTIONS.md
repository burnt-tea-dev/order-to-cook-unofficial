# 玩家全身與第一人稱端點

觀察日期：2026-11-06 HKT；配對來源版本 `0.1.26-alpha.1`。這是來源與生成結果驗證，沒有新開 BDS，也沒有觀察真 client。動作語義、骨架分界及 Java 兩分支的實際 renderer 入口統一見 [PARITY](../../PARITY.md#玩家動作的來源與骨架)；本頁只記本批反例與檢查結果。

三個可重現的差異已在真生成器修正：

- 手洗第一人稱仍把整臂畫成12像素，原右肩到手端只有11.1836757342像素。現在按來源肩手距縮放，同時補償位移，保持既有鏡頭肩端。
- 拍手沒有套原 body 下移2像素，也遺失前臂及足部對末端的影響。現在拍手與安坐都從原片段生成，保留來源轉折、20 TPS 取樣及非循環末幀。
- 原測試將 native 腿中心當成±2；Mojang 所選版本的實際中心是±1.9。改用實際網格位置後，舊生成器出現0.1像素差；新結果保留原髖／足端。

`tests/test_appliance_geometry.py` 的20項測試通過。測試呼叫真生成器，再以來源與 native 父子骨架正向計算身體、肩手、髖足位置；沒有把生成器的反向擬合算法複製成預期值。第一人稱還檢查來源臂長及原鏡頭肩端。生成測試使用 Python3.14.4／Pillow12.1.1；正式 CI 使用既有固定工具版本。

`npm run verify` 的540項測試全部通過，包含44項椅子服務及8項手洗／拍手顯示條件測試；tsc、資源檢查與配對打包成功。實際服務測試確認坐下／重載恢復、離座／換座停止、60 tick 拍手、原0／12／20 tick聲音，以及持物仍可拍手且不改庫存／訂單。實際生成條件測試確認兩動作各自清除 request、FP／TP／VR／UI／持物／時間邊界；這個 JavaScript 共用子集執行不代表原生 Molang 或 renderer 求值順序已驗證。來源權利鏈及發布政策檢查無錯誤，既有權利範圍待澄清項維持 advisory。

兩個 request 名以 [player-presentation.json](../../../player-presentation.json) 為唯一來源。共享 producer 需採用 Core `e8dbc451d307625d1859ac863b4299665449eb52` 的多 request 接口；OTC 自身不攜帶有效 player／FP controller 覆寫。來源合併不自動修改已凍結候選或 LIVE。

目前仍是整根手臂／腿的端點近似。真分段肘膝、Java ACTION 絕對鏡頭校準、Slim／客製 avatar、持物時的 Java 雙臂替換，以及 client 圖層／可見起停尚未完成。保留原 classic／slim 完整分段 rig 不代表它已接為有效玩家 geometry；這些限制不能由本批來源測試或舊原生報告推定完成。
