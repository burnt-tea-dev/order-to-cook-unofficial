# 未發布來源修正：菜單與訂單的食品變體

基線：`a118cd5a15cd02652b66d91a0524ca8c04cbbb03`。本輪延續 T1a 讀取器，補上菜單／訂單／扣料的玩法連接；不是完整 T1b 食品目錄或配方整合。

## 玩家可見行為

- 可識別食品含有效公開 `nativeVariant` 時，使用物品 ID＋變體建立菜品。不同變體可分開登記、點餐及移除；通用條目與同 ID 的指定變體不能同時計算營養。
- 菜名、營養及變體在登記／出單時複製保存。後續食品設定或菜單編輯不改寫已接訂單；既有菜單採用新設定需明確移除後重新登記。
- 訂單、票據、成品說明和缺料提示使用該筆訂單保存的名稱與變體，不再拿最新全域名稱冒充原報價。
- 背包選菜的表單返回後重新核對實際物品、食品識別及資料；被移走／換料／更名／更改營養設定時拒絕舊選擇，且不扣除物品。
- 備料先分配指定變體，再分配歷史 ID-only 條目。同一格即使滿足多條要求也只扣一次；錯誤變體不被拿來頂替，失敗時盤數、供應品及訂單狀態保留。

## 相容邊界

沿用 Core V1 讀取器與原始公開欄位，沒有改 SDK、另造 V2、讀取外包私人屬性或覆寫 lore。只保存 `{carrier, nativeVariant}`；熱度、品質及調味不作菜品主鍵或報酬倍率，食品冷卻不會令已接訂單變得無法完成。短時間扣料預檢仍比較完整可讀原始資料，拒絕計畫完成後的換料。

未帶變體的舊記錄繼續按 ID 匹配，不做猜測式存檔遷移。不支援原始 lore 的引擎不能履行指定變體要求，但舊 ID-only 訂單繼續可用；損壞的指定變體要求不會降級成通用要求。

V1 不提供食品分類或營養，這輪沒有自動接入 Grilling、Tavern、World Liquor 的完整目錄，沒有推導私人秘製串內容，也沒有新增／轉移任何爐灶配方。飲用效果、品質經濟、Cookery 指南排版、UUID、存檔 key、LIVE 及正式 Release 均未改動。

- 真實 BDS、保存世界重啟、多人、鍵鼠／觸控客戶端及 Java 畫面對照：未執行。這些單元／整合測試不代替客戶端驗收。
