# 未登記椅子探索：獨立設計，未實作

本設計不屬於 #63 第一批規則候選，沒有啟用世界掃描、POI 或性能優化。固定 Java 基準及生成規則見 [來源稽核](../validation/NPC_SPAWN_PARITY_AUDIT.md)。

## 問題與責任界線

`ctx.stations()` 只提供已登記椅子，無法完整發現指令放置、結構導入、舊世界等未登記方塊。Forge 的 normal 與 walk-in 查找會讀世界方塊，水平圓半徑 24、Y±8（裁切世界範圍）；normal 按 x↑、z↑、y↓，walk-in 收集合格池後均勻取樣。不能把「先查登記椅子，查不到才掃世界」當作相同順序：較前的未登記椅子本來應優先。

探索只產生位置候選；實際椅子、流體／頭部空間、佔用及臨時 claim 仍由 entity service 最後核對。不要在發現時認領 owner、複製餐廳、寫入第二套持久位置庫、清除未知舊資料或產生 NPC。

## 可評估路線

優先與 #11 的原生 POI 候選層協調，核對是否能完整列出當前已載入的 `ordertocook:chair`。僅將本次回傳位置與已登記候選合併去重，再按 Java 座標序排列；POI 不代表權限、佔用、完整性或長期有效性。實驗開關、API 版本與載入能力均由整合代理決定，不加入假裝等價的自動 stable 降級。

若另評估 stable 世界掃描，先規劃每 tick 有上限的短生命週期查詢工作；正常顧客必須依原掃描順序逐段處理，walk-in 必須在整個可查詢範圍完成後才能抽樣，不能對第一批就隨機取人。半徑 24 的圓盤有 1793 個 XZ 柱，未裁切的 17 層共 30481 格，還未計頭部／佔用查詢；不應每位顧客每 tick 全掃。此計數只是靜態上界，不是效能結果。

## 載入與失敗規則

任何路線都不加 tickingarea、不強載、不建立保活 tickets。讀取前確認載入，讀取中卸載／例外保持 unknown；未知不等於不存在，不能據此清除登記或宣稱沒有椅子。查找需區分 ready、no-eligible-loaded-chair、incomplete，將不完整資訊交還既有 admission／retry owner，不能用空陣列冒充完整掃描。

跨 tick 檢索完成後重驗世界位置、餐廳 canonical 身分、訂單仍有效、椅子和 headroom、fluid、佔用及 chair claim；生成前取得既有 claim。訂單失效／餐廳移除就丟棄暫態查詢，不另建 pending 訂單或永久負快取。若要在掃描中途返回 normal 的第一合格椅子，必須確定它之前的已載入候選已全部檢查；未知區塊的處理屬明示平台適配，不能稱作完整 Java 世界掃描。

## 後續驗證與合併條件

在獨立分支證明：有較早未登記椅子時的排序；登記與 POI 重複不加權；全部方塊／頭部空間檢驗、玩家與其他 LivingEntity 佔用；部分區塊 unknown 不被當成確定不存在；拆建／載入變化不留下陳舊 claim；查詢期間訂單或餐廳失效不生成。既有保存失敗、去重和原生未知結果界線仍適用。

性能必須以相同候選集合、同世界密度、相同查詢工作及載入條件量測；分開 CPU、查詢成本與原生 tick 結果。#11 既有高密度退化沒有因為這份設計而改善。沒有原生／客戶端測量前，不得聲稱 POI 已改善或完成遊戲驗收。
